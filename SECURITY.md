# Security and private evidence reporting

Do not disclose a vulnerability, Bluetooth address, account detail, health value, raw
capture, application archive, or vendor payload in a public issue or pull request.

Use GitHub's private “Report a vulnerability” flow for this repository:
https://github.com/Pipeliner/jring-client/security/advisories/new

Begin with a minimal text description. Do not attach sensitive evidence until the
maintainer confirms the minimum needed and a handling plan. If the private form is not
available, open a public issue containing only “private security contact requested”;
include no technical details or identifiers.

The maintainer should acknowledge receipt, agree on retention/deletion and publication
scope, reproduce with the smallest sanitized artifact possible, and coordinate a fix
before any public disclosure. This document does not promise a response deadline or
create authorization to test hardware, accounts, or systems you do not own.
